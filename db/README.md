# 数据库与迁移

推荐通过根目录的 `compose.yaml` 启动独立 MySQL 8.4。首次空卷初始化执行01–08表结构、10–14演示种子和 `migrations/`。正常重启不重置数据。

`00_create_database.sql` 会删除同名数据库，只作为历史初始化脚本保留，Compose 明确排除它。不要把全量 schema 脚本作用于已有数据库。

已有数据库：先备份，只执行 `migrations/` 中尚未应用的脚本。迁移01新增语义向量表，02新增演示语料，03给检索测试记录增加策略与证据字段。DDL 可能隐式提交，中断后应先检查已完成的语句，不可盲目重复执行 ALTER TABLE。

Compose 独立数据库可执行 `docker compose exec db sh /workbench-deploy/migrate.sh`。脚本以文件名和 SHA256 记录迁移，已应用文件不得修改；正常重启不自动清库或重放迁移。外部数据库应沿用自己的迁移登记流程。

演示迁移使用1001–1009与10001起的保留ID。若既有系统占用这些ID，应先调整尚未应用的演示迁移，不能覆盖已有数据。已有数据卷追加演示文档后，应在知识库页面显式重建 BM25 / 哈希索引；正式评测会检查全量在线切块的索引完整性。

15–29中的旧清理、恢复和运营演示脚本不是正常启动流程的一部分。历史设计口径见 [原数据库说明](../docs/archive/database-README.md)。

语义索引通过现有权限接口显式构建，默认重建仍为哈希索引。向量配置指纹不含密钥；内容修改后旧语义向量失效，重建完成前普通检索回到本地基线，严格实验报错。
