# 项目定位与 AI 改造范围

## 一句话定位

**以采购业务为演示载体，展示如何把 AI 能力接入一个已有 Java/Vue 系统，并通过权限约束、依据核验、保守降级和评测使改造可验证。**

项目面向 AI 应用工程和 Java 全栈岗位的能力展示，采用独立的产品说明、使用流程、技术决策、验收标准与发布记录。业务数据与制度为虚构演示内容，当前交付范围为可复现的本地应用。

## 展示的核心能力

1. **接入已有系统**：在现有服务、数据模型与角色权限上增加自然语言入口，复用业务约束。
2. **约束 AI 行为**：意图、实体、参数和权限均由服务端校验；AI 输出不能直接成为数据库执行指令。
3. **组织可核对的答案**：知识问答关联有效片段，校验引用、数值与单位，清楚区分生成答案和参考原文。
4. **处理不确定性与故障**：有歧义先澄清，模型异常保守降级，证据不足明确拒答。
5. **以证据评估方案**：固定语料和题集比较检索策略，区分真实模型结果、模拟故障与未完成实验。

## AI 层与业务底座

| 层次 | 职责 | 展示方式 |
|---|---|---|
| AI 交互与路由 | 接收问题、识别任务、组织结果与会话 | 首页、AI 对话 |
| 受控查询与知识问答 | 权限内查数据、检索文档、验证引用、保守降级 | 订单/库存问句、制度问句、角色切换 |
| 检索与验证 | 索引兼容、策略对照、故障与权限测试、查询审计 | 知识库与检索实验、审计、原始报告 |
| 采购业务基础 | 提供订单、库存、事务、文档与角色约束 | 折叠的业务验证环境、业务明细页面 |

采购申请、订单、验收、入库等模块用于构造完整可核对的场景。新需求优先服务于 AI 接入、可靠性或可验证性；仅增加业务 CRUD 的功能不作为当前主线。

## 产品入口

首页优先展示 AI 对话、查订单、查库存、问制度和最近会话；知识库/检索实验及查询审计按权限展示。业务指标和维护入口默认折叠。侧栏将 AI 能力置于业务模块之前，保留业务入口以核对查询结果与执行人工处理。

示例问题只预填，由用户确认后提交。问答历史继续使用原结果 JSON，新字段可选，旧记录正常展示。

制度问答增加 `answerMode`：`generated` 为生成回答；`references_only` 为仅供参考原文；`refused` 为无可靠依据的拒答。后两者均使用原 `NoData` 结果码。数据查询的 `NoData` 仍表示无匹配数据，不改变其语义。

## 成果与沿革边界

仓库保留既有代码与提交历史，基线为 `portfolio-baseline-2026-11-09`。既有版本已包含采购业务和部分 AI 查询/问答能力；本次新增重点是 AI 优先的产品体验、数值与引用守卫、保守降级、上下文权限边界、语义检索适配与对照评测、可复现交付。不能把既有模块或已有 AI 能力全部记作本次新增。

历史材料隔离在 `docs/archive/`，只用于来源与旧版行为追溯，不作为当前产品导航、演示脚本或验收依据。内部 Java 包、模块编号、路由与权限编码保留兼容，其名称不决定产品定位。

## 简历与演示主线

围绕“接入业务系统 → 约束模型行为 → 验证结果与故障边界 → 对照评测 → 可复现交付”讲解。每项贡献需对应实际代码和原始测试证据；模型效果和性能指标只引用已运行且可追溯的结果。具体话术和流程见[演示与简历素材](demo-script.md)，待完成项见[实施记录](implementation-status.md)。
